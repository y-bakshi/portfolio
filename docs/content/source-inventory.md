## Original Sources Outside This Repository

The owner's separate `cv` project contains `source/master_resume.md` and role-specific résumés under `best 5/`. Those files are not part of a clone of this repository; local sibling-folder access must not be a build dependency. Ask the owner for an approved current résumé and underlying evidence when preparing publication content.

The completed handoff deliberately uses an in-repository summary rather than copying the entire CV library. No phone number, email address, private employer repository, credential, or internal release-authority name is needed to implement the UI.

## Evidence Record to Introduce

For each project maintain stable ID, title, category, team context, exact contribution, stack, problem, solution, results, measurement status, evidence references, repository/demo links, and last review date. Final content collections and the assistant knowledge artifact must derive from the same reviewed source.

Do not promote items from the CV project's future build plan into completed experience. Avoid screenshots or proprietary details from employer systems unless approved for publication.

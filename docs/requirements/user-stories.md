# User Stories

| ID | Persona and goal | Done when |
| --- | --- | --- |
| US-01 | As a recruiter, I want to understand Yash's focus quickly. | Hero and About convey AI engineering, backend depth, and verified professional context without requiring the assistant. |
| US-02 | As a recruiter, I want evidence relevant to a role. | Category filters and assistant suggestions surface projects with attributable contributions and outcomes. |
| US-03 | As a developer, I want to assess system design. | Case studies contain architecture diagrams, constraints, implementation detail, and available repository links. |
| US-04 | As a visitor, I want answers grounded in real work. | Personal claims link to portfolio evidence; missing information is explicitly acknowledged. |
| US-05 | As a visitor, I want a guided tour without losing control. | A project is highlighted, opening its page requires my choice, and I can stop or dismiss guidance. |
| US-06 | As a visitor using touch, I want comfortable interaction. | Controls are reachable, the virtual keyboard does not cover input, and reading/scrolling remains usable. |
| US-07 | As a desktop visitor, I want a rich editorial layout. | Columns, diagrams, navigation, and metadata use available space without excessive line lengths. |
| US-08 | As a visitor who cannot or prefers not to speak, I want equivalent text interaction. | Microphone permission is optional and all answers/actions remain available through text. |
| US-09 | As a hiring manager or collaborator, I want to contact Yash. | Email, LinkedIn, GitHub, and configured scheduling options are clear and operable. |
| US-10 | As a privacy-conscious visitor, I want to understand retention. | A brief notice explains stored redacted questions, optional feedback, retention, and third-party voice processing. |
| US-11 | As the owner, I want predictable AI cost. | Daily/global budgets, input limits, cache hits, and kill switches are monitored and verified. |
| US-12 | As a returning visitor, I want the site usable when AI is unavailable. | Case studies, résumé, filtering, and contact work without backend inference. |

Use [functional IDs](functional-requirements.md) and [test cases](../testing/test-cases.md) when translating these stories into tasks.
